# Решение проблем

Начните с журналов. Команды Docker выполняйте из `tolktak/deploy`:

```sh
docker compose ps
docker compose logs --tail 100 tolktak livekit
```

## Сервер не запускается

Проверьте сообщение в журнале: обычно это отсутствующий `LIVEKIT_PUBLIC_URL`, ключ или секрет LiveKit, секрет короче 32 символов либо неизвестное значение `TOLKTAK_REGISTRATION`.

`address already in use` означает занятый порт. Измените его по [инструкции](../guides/firewall.md) и проверьте значения в `.env` и `livekit.yaml`.

## Приложение не подключается

1. Откройте адрес сервера в браузере на том же устройстве. Если страница недоступна, проверьте DNS, файрвол и прокси.
2. При ошибке сертификата проверьте срок действия и доверие системы. [Самоподписанный сертификат](../guides/certificates.md) должен быть установлен в доверенные.
3. Для публичного IP без HTTPS укажите протокол и порт явно: `http://203.0.113.10:8080`. Иначе приложение предполагает HTTPS.

## Чат работает, голоса нет

| Симптом | Что проверить |
|---|---|
| Подключение к комнате сразу завершается ошибкой | `LIVEKIT_PUBLIC_URL` должен быть доступен с устройства участника. Для HTTPS — `wss://`, для HTTP — `ws://`. Адрес `https://lk.example.com` в браузере должен отвечать `OK` |
| Комната открывается, звука нет или связь обрывается примерно через 15 секунд | UDP-порты в файрволе сервера и панели хостинга |
| Работает не у всех | TCP 7881 и TURN: UDP 3478 и relay-диапазон. Они нужны для строгих сетей и NAT |
| Имя LiveKit находится за CDN | Отключите проксирование для этого DNS-имени |
| На машине есть VPN или несколько интерфейсов | `rtc.interfaces` в `livekit.yaml`: LiveKit может предлагать недоступные клиентам адреса |
| В списке остаются вышедшие участники | `webhook.urls` должен достигать сервера TolkTak. Список также сверяется каждые 20 секунд |

Подробности и команды — в [инструкции по портам](../guides/firewall.md).

## Микрофон не слышно

Проверьте выбранное устройство в настройках TolkTak, системное разрешение на микрофон и режим push-to-talk. На macOS и Linux push-to-talk работает при активном окне приложения. Если не слышно всех участников, сначала проверьте медиасоединение выше.

## Файл не загружается

HTTP 413 означает превышение лимита в TolkTak или в прокси. `client_max_body_size` nginx должен быть больше `TOLKTAK_MAX_UPLOAD_MB`.

## Приложение постоянно переподключается

Прокси может закрывать WebSocket. Проверьте передачу Upgrade-заголовков и тайм-аут чтения больше 70 секунд. Готовая конфигурация есть в [инструкции nginx](../guides/reverse-proxy.md).

## Как сообщить об ошибке

Откройте [issue](https://github.com/D4eNst/tolktak/issues), укажите систему, версию приложения и сервера, шаги воспроизведения и относящиеся к ошибке строки журнала. Версию сервера показывает `/api/v1/server`.

Уберите из журнала токены, пароли, секреты и личные данные. Уязвимости сообщайте [приватно](../security.md).
