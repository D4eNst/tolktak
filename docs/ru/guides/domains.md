# Домены и адреса

## Одно имя для HTTPS

Участники подключаются к TolkTak и LiveKit по одному имени. Обратный прокси направляет путь `/rtc` в LiveKit, а всё остальное — в TolkTak.

| Имя | Тип записи | Значение |
|---|---|---|
| `chat.example.com` | A | `203.0.113.10` |

Имя и IP в таблице — примеры. В DNS нужны свой домен и публичный адрес сервера. Запись AAAA добавляется только при настроенном IPv6: иначе часть устройств может пытаться подключиться по недоступному адресу.

## Проверка DNS

```sh
dig +short chat.example.com A
```

Для записи без проксирования команда должна вернуть публичный IP сервера. После обновления DNS изменения могут появиться не сразу. В [установке через Compose](../install/compose.md) то же имя записывается в `TOLKTAK_DOMAIN` в `.env`; Caddy получит сертификат, когда имя начнёт указывать на сервер.

## Проксирование у DNS-провайдера

Инструкция рассчитана на прямое подключение к серверу. У провайдера с CDN-прокси для имени используется режим **DNS only**. В нём DNS возвращает адрес самого сервера; описание режима есть в [справке Cloudflare](https://developers.cloudflare.com/dns/proxy-status/).

Звонки идут напрямую на порты сервера 7881/TCP и 7882/UDP. Обычный HTTP-прокси этот трафик не передаёт.

## Один адрес без сертификата

[Сервер, запущенный через `docker run`](../install/docker.md), работает по HTTP на своём адресе:

- `http://192.168.1.20:8080` — TolkTak;
- `ws://192.168.1.20:7880` — LiveKit. Этот адрес сервер сообщает приложению сам, исходя из адреса, по которому оно подключилось.

Вместо `192.168.1.20` нужен адрес своей машины. Пароли, переписка и файлы в режиме HTTP передаются без шифрования. Для подключения через интернет — [HTTPS и сертификаты](certificates.md).
