# Домены и адреса

## Два имени для HTTPS

В стандартной конфигурации TolkTak и LiveKit находятся на одной машине, но используют разные имена. Обратный прокси направляет запросы к нужному сервису.

| Имя | Тип записи | Значение |
|---|---|---|
| `talk.example.com` | A | `203.0.113.10` |
| `lk.example.com` | A | `203.0.113.10` |

Имена и IP в таблице — примеры. В DNS нужны свои домены и публичный адрес сервера. Запись AAAA добавляется только при настроенном IPv6: иначе часть устройств может пытаться подключиться по недоступному адресу.

## Проверка DNS

```sh
dig +short talk.example.com A
dig +short lk.example.com A
```

Для записей без проксирования обе команды должны вернуть публичный IP сервера. После обновления DNS изменения могут появиться не сразу.

Эти же имена передаются скрипту настройки: сначала TolkTak, затем LiveKit.

```sh
./init.sh talk.example.com lk.example.com
```

## Проксирование у DNS-провайдера

Инструкция рассчитана на прямое подключение к серверу. У провайдера с CDN-прокси для обоих имён используется режим **DNS only**. В нём DNS возвращает адрес самого сервера; описание режима есть в [справке Cloudflare](https://developers.cloudflare.com/dns/proxy-status/).

Медиапорты LiveKit и TURN должны быть доступны напрямую. Обычный HTTP-прокси не передаёт UDP-трафик.

## Один адрес без сертификата

В локальной сети можно использовать один адрес с разными портами:

- `http://192.168.1.20:8080` — TolkTak;
- `ws://192.168.1.20:7880` — LiveKit.

Конфигурация для такого примера создаётся командой:

```sh
./init.sh --http 192.168.1.20
```

Вместо `192.168.1.20` нужен адрес своей машины. Пароли, переписка и файлы в режиме HTTP передаются без шифрования. Для подключения через интернет — [HTTPS и сертификаты](certificates.md), затем [обратный прокси](reverse-proxy.md).
