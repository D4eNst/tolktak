Архитектура

У TolkTak три основных компонента: приложение, сервер данных и LiveKit. Эта страница объясняет их связь и границы доверия.

Компоненты#

Приложение (Electron + Preact)
    │ HTTPS / WSS                │ WebRTC / WSS
    ▼                            ▼
TolkTak Server ── токены ──▶ LiveKit SFU
    │          ◀── webhooks ──
    ▼
SQLite / PostgreSQL + файлы

В Electron основной процесс управляет окном, треем, горячими клавишами, захватом экрана и обновлениями. Preload предоставляет ограниченный IPC-мост. Renderer содержит интерфейс Preact, клиент REST/WebSocket и livekit-client.

Python-сервер использует FastAPI, Uvicorn и Tortoise ORM. Он хранит аккаунты, группы, каналы, сообщения и загрузки, выдаёт токены доступа к комнатам и обрабатывает webhooks LiveKit. SQLite работает в WAL-режиме; PostgreSQL выбирается через TOLKTAK_DATABASE_URL. Миграции запускаются при старте.

Сервер рассчитан на один процесс на базу: WebSocket-подключения и ограничения частоты запросов находятся в памяти. Простое увеличение числа Uvicorn workers не является поддерживаемым масштабированием.

Сообщения и события#

Клиент использует REST API под /api/v1/ и один WebSocket для событий. Ping отправляется раз в 25 секунд; 70 секунд без кадров считаются потерей соединения. После переподключения клиент запрашивает пропущенные сообщения.

Сообщение содержит nonce, сгенерированный клиентом. Пара «автор + nonce» уникальна, поэтому повтор запроса после разрыва связи не создаёт дубликат.

LiveKit сообщает о входе и выходе участников через webhooks. Раз в 20 секунд TolkTak также сверяет активные комнаты через API LiveKit, чтобы исправить состояние после пропущенного события.

Голос, видео и экран#

После проверки членства сервер выдаёт LiveKit-токен на одну комнату, действующий 12 часов. Приложение публикует дорожки, LiveKit пересылает их участникам без смешивания и перекодирования. Основной транспорт — UDP; при ограничениях сети используются TCP или TURN.

Микрофон проходит локальную цепочку обработки в AudioWorklet: выбранное шумоподавление (RNNoise, GTCRN или DeepFilterNet3), фильтр, выравнивание громкости, компрессор, лимитер и управление активацией голоса. Модели работают через WebAssembly на процессоре устройства. Голос передаётся в Opus с DTX и RED.

Видео и демонстрация используют H.264 при доступном системном кодировании, иначе VP8. Simulcast позволяет передавать разное качество разным зрителям. Клиент получает полный слой открытой трансляции и меньший для превью. В фоне он сокращает получение превью и камер; это поведение можно отключить в настройках.

На Windows 11 WASAPI process loopback захватывает звук дерева процессов выбранного окна. При демонстрации экрана звук TolkTak исключается, чтобы не возвращать голоса участникам. На Windows 10 доступен общий loopback, на macOS и Linux звук демонстрации не передаётся. DRM не обходится: защищённое видео может отображаться чёрным.

Модель безопасности#

Сервер рассчитан на участников, которые доверяют его владельцу.

Шифрование#

HTTPS на прокси защищает API и файлы в пути. DTLS-SRTP защищает медиа между каждым клиентом и LiveKit. Сквозного шифрования нет: LiveKit обрабатывает расшифрованное медиа, а база и файлы хранятся без шифрования на уровне приложения.

Аккаунты и сессии#

Пароли хешируются Argon2id: 3 итерации, 64 МБ памяти и 2 потока. Вход выдаёт случайный 256-битный токен; база хранит только SHA-256-хеш. Сессия действует до выхода. WebSocket принимает токен первым кадром, а не в URL.

Первый аккаунт становится администратором. Регистрацию можно ограничить приглашениями. Сервер ограничивает частоту входа, регистрации, отправки сообщений, реакций и загрузок. За прокси адрес клиента берётся из X-Forwarded-For, только если включён TOLKTAK_TRUST_PROXY.

Доступ и файлы#

Сообщения и голосовые токены доступны участникам соответствующей группы или личного канала. Токен LiveKit ограничен одной комнатой. Webhooks проверяются по подписи и хешу тела.

Загрузки получают случайный 128-битный идентификатор. Тип определяется по содержимому. Только разрешённые типы изображений, аудио и видео показываются inline; остальные выдаются как скачиваемые файлы. Ответы содержат Content-Security-Policy: sandbox и X-Content-Type-Options: nosniff.

Скачивание файла не требует входа: любой, у кого есть ссылка, может получить файл. Удаление сообщения не удаляет сам файл с диска. Голос и видео сервером не записываются.

Приложение#

Renderer работает с sandbox и contextIsolation, без Node.js integration, под CSP. IPC-мост допускает только перечисленные операции. Переход на сторонние страницы блокируется.

Токен на диске защищается Electron safeStorage: DPAPI на Windows, Keychain на macOS, Secret Service на Linux. Без системного хранилища используется файл, доступный только пользователю. Electron fuses отключают RunAsNode, NODE_OPTIONS и флаги инспектора, включают проверку ASAR.
