Обратный прокси

В конфигурации с HTTPS прокси принимает запросы на порту 443 и передаёт их локальным сервисам. Сертификаты хранятся на нём; TolkTak и LiveKit слушают 127.0.0.1.

Имя Локальный адрес
talk.example.com http://127.0.0.1:8080
lk.example.com http://127.0.0.1:7880

Это пример с портами по умолчанию. При изменении портов в конфигурации проекта адреса в прокси также меняются. Медиапотоки идут к LiveKit через отдельные порты.

nginx#

Скачать пример конфигурации

Тот же файл находится в репозитории: deploy/nginx.conf.example. Он содержит настройки обоих имён, WebSocket и лимита загрузки файлов.

  1. Добавить содержимое примера в конфигурацию nginx, например в /etc/nginx/conf.d/tolktak.conf.
  2. Заменить домены, локальные порты и пути к сертификатам.
  3. Проверить конфигурацию и применить её:
sudo nginx -t && sudo systemctl reload nginx

Команда systemctl подходит для системы с systemd. Пример использует http2 on из nginx 1.25.1 и новее; в более ранних версиях эту строку можно убрать.

Основные параметры#

Параметр Назначение
Upgrade, Connection Передача WebSocket для событий чата и подключения к звонкам.
client_max_body_size Лимит тела запроса. В примере 60m при лимите файла TolkTak в 50 МБ.
proxy_read_timeout Ожидание данных от сервиса: 120 секунд для TolkTak и 3600 для LiveKit в примере.
X-Forwarded-For Адрес участника для ограничения частоты запросов.

При изменении TOLKTAK_MAX_UPLOAD_MB лимит nginx должен оставаться выше с учётом служебных данных запроса. Превышение лимита возвращает HTTP 413. Передача WebSocket описана в документации nginx.

TOLKTAK_TRUST_PROXY=1 используется, когда к TolkTak можно обратиться только через доверенный прокси.

Проверка#

curl https://talk.example.com/healthz

Вместо примера нужен свой домен. Ответ ok подтверждает доступ к TolkTak через HTTPS. Звонок и трансляция проверяются отдельно с двух аккаунтов, желательно из разных сетей.

Для другого прокси сохраняются те же адреса сервисов, поддержка WebSocket и лимит загрузки файлов. При проблемах — диагностика подключения.
