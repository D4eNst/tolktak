Файрвол и порты

Откройте входящие порты в файрволе ОС и в панели хостинга. Если сервер за роутером, также настройте проброс. init.sh печатает фактические порты вашей конфигурации.

Какие порты нужны#

Порт Протокол Назначение
443 TCP HTTPS
80 TCP Только если используется получение сертификата через HTTP-01
8080, 7880 TCP Прямой доступ к TolkTak и LiveKit при HTTP; при HTTPS наружу не нужны
7881 TCP Медиа для клиентов с заблокированным UDP
50000–60000 UDP Голос и видео
3478 UDP TURN
30000–40000 UDP TURN relay

Пример для ufw и HTTPS:

sudo ufw allow 443/tcp
sudo ufw allow 7881/tcp
sudo ufw allow 50000:60000/udp
sudo ufw allow 3478/udp
sudo ufw allow 30000:40000/udp

Доступ по SSH должен оставаться разрешён. Не включайте файрвол на удалённой машине, пока не проверили правило для своего SSH-порта.

Изменение портов#

При первом запуске передайте нужные значения в окружении:

TOLKTAK_PORT=18480 LIVEKIT_PORT=17880 \
RTC_UDP_START=55000 RTC_UDP_END=55499 \
TURN_RELAY_START=55500 TURN_RELAY_END=55999 \
./init.sh talk.example.com lk.example.com

Скрипт запишет значения в .env и livekit.yaml. Изменения только в .env недостаточно: LiveKit читает свои порты из YAML.

Для повторной генерации сначала сохраните старые .env и livekit.yaml, затем запустите init.sh заново. Он создаёт новые ключи LiveKit, поэтому после этого перезапустите оба сервиса.

Сервер за NAT#

Пробросьте каждый используемый порт на внутренний адрес машины. rtc.use_external_ip: true в livekit.yaml позволяет LiveKit определить публичный IP через STUN.

На машине с VPN, Docker-мостами или несколькими интерфейсами ограничьте rtc.interfaces, чтобы клиенты не пробовали недоступные адреса. Если чат работает, а голос нет, используйте диагностику подключения.
