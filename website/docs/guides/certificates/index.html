HTTPS и сертификаты

HTTPS защищает пароли, сообщения и файлы при передаче между устройством и сервером. В конфигурации TolkTak сертификаты устанавливаются на обратном прокси.

Публичный сертификат#

Для сервера в интернете нужен доверенный сертификат на каждое из двух имён. Один сертификат также может покрывать оба имени.

  • nginx: получение и продление через ACME-клиент, например Certbot. Центр сертификации Let's Encrypt выдаёт бесплатные сертификаты.
  • Caddy: автоматическое получение и продление для доменов в конфигурации.

При ручной настройке ACME-клиента доступны разные способы подтверждения домена:

Способ Что требуется
HTTP-01 Домен указывает на сервер; порт 80/TCP доступен из интернета.
DNS-01 TXT-запись в DNS. Подходит при закрытом порте 80 и для wildcard-сертификатов.

Условия описаны в документации Let's Encrypt. Продление должно быть автоматическим; после замены сертификата nginx требуется перечитать конфигурацию.

Самоподписанный сертификат#

Для закрытой сети возможен сертификат собственного центра сертификации. Такой вариант требует отдельной настройки доверия на каждом устройстве участников.

Имя или IP сервера должны быть указаны в поле Subject Alternative Name. Приложение не отключает проверку сертификатов: недоверенная цепочка, несовпадение имени или истёкший срок помешают подключению.

Работа без сертификата#

Для локальной сети доступен режим HTTP:

./init.sh --http 192.168.1.20

Здесь используется адрес своей машины. Пароли, сообщения и файлы передаются без шифрования HTTP. Голос и видео между приложением и LiveKit защищены DTLS-SRTP; сквозное шифрование в TolkTak пока не реализовано.

Настройка маршрутизации HTTPS — в разделе «Обратный прокси».
